# 装修市场实施边界

本仓库继续是主游戏共用的视觉层。装修市场以现有Showroom扩展，不另建与主游戏脱节的产品。

## Phase 0：已核对

- 基线提交：`09da94cbb618b454e29897bcced3de51d4241a40`。现有主题`default`与`cyber`均绑定`hq-fixed-layout-v1`。
- 场景代码、UI组件、资源catalog和Showroom在本仓库；真实账号、员工、位置、导航、任务、审批、数据与MCP属于私有宿主。
- 已有模型与主题校验不等于市场审核；现有冷蓝主题也不作为“全新科幻装修已完成”的证据。

## 按顺序交付

1. 主题包格式、真实字节/hash/许可校验与固定来源提交。
2. Showroom内市场目录、筛选、详情、真实3D预览与下载；空目录如实显示，不虚构精选、下载量或认证。
3. 私有宿主独立总部审核、冻结版本、上架/下架和受控索引。未上架版本不进入公开API。
4. 公司侧老板授权、私有草稿、审批应用、审计与回滚。
5. 同一渲染/编辑引擎支持公共本地文件和公司授权存储；不共享权限或数据。
6. 装修Action/MCP复用真实员工授权，AI只可创作/提交，不可发布/审批/提权或擅自公开。
7. 默认精致暖阳总部与实质不同的科技装修，安全热切换保留角色与业务状态。
8. 端到端测试、真实浏览器截图、分阶段提交和可回滚发布。

## 审核契约

总部市场审核资格与公司老板权限独立。审核通过不应用任何公司；公司私有草稿不自动公开；市场试装只能生成草稿，正式应用必须由老板真人批准。主题包不得执行远程代码、改动碰撞、门禁、角色或员工身份。

第一阶段以GitHub PR投稿，不开放匿名任意文件上传。技术校验只判断包的可接受性，不能替代人工版权与视觉审核。开放许可资源仍保留原始仓库获取方式。

当前文档是实施路线；阶段完成以代码、测试和实际验收为准。生产数据库迁移、密钥、公开发布和正式环境切换须由项目所有者确认。
