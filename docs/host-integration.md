# 主游戏如何使用这个仓库

主游戏在工程根目录下以 `visual-studio/` 检出本仓库。它直接import共用的 `src/office.ts`、主题模块、UI视图和样式，不依赖一份会漂移的复制版。

主工程应固定审核通过的提交：拉取/检出该提交 → `npm ci` → 验证主题和资源 → 主工程类型检查与全部业务测试 → 在独立输出目录构建 → 本地真实画面检查 → 按正式发布流程切换。不要自动跟踪远程最新版，也不要让游戏自己拉取并执行别人提交的源码。

宿主提供：WebGLRenderer/Scene、实际项目作品图片、本人头像与动画、相机/输入、服务端位置、权限和事件、登录与请求层。`OfficeVisuals`只返回视觉Root、办公室门与遮挡网格、通用角色工厂；不会读写员工、稿件和财务。

UI视图通过 `api/open/cleanup/walk/owner` 等既有接口接入宿主；业务合法性仍由服务端验证。展厅的 `apps/showroom/fixtures.ts` 仅提供已标记示例的少量读取，所有写入拒绝。主游戏绝不导入该文件。

宿主Vite配置使用 `resolve.dedupe: ['three']`，避免本仓库独立安装后引入两套Three.js。构建时仅复制资源目录中经过catalog允许的文件；当前本地宿主已集成该路径。开发时若新增替换模型，也应让宿主静态目录提供该资源；正式构建插件会同步已登记资源。

视觉仓库不包含后端、MCP服务器、账号系统或客户数据。它只覆盖展示层，不声称解决所有员工操作协议或飞书接入。角色状态不在主题Root内，因此换肤不应重建员工。是否真的保留状态，需要在主工程验证。
